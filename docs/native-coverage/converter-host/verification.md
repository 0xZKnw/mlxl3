This chunk wires an explicit native backend through the maintained advanced converter. The user-facing Studio and automatic capture pipeline still use their existing backend until raw source capture, grouped expert scale policy, and packaging are ported. No throughput comparison is part of this work.

The production path is `ponyexl3.cli.convert_advanced` → source/plan readers → direct or per-layer LDLQ → `mlxl3_quantizer.native.converter_tiles` → the standalone `quantize-tiles` engine command → the existing CPU packing and checkpoint writer. The native service and its 21 search/codebook specializations were qualified in PR 98. This branch changes the Python host path and preserves the service's exact binary protocol.

The native backend requires `MLXL3_NATIVE_ENGINE`. It never falls back to MLX. Its service calls are serialized across measurement workers and bounded to one scratch launch each. The converter's existing cancellation flag is checked before allocation and while waiting for the child. Missing executables, invalid native configurations and malformed child payloads are fatal errors; the source driver's unsupported-module skip handling must not conceal service failures. The standalone Python tile API keeps its existing explicit engine argument.

For source weights with oracle scales, the native basis uses owned FP32 Hadamard butterflies with the Metal subnormal flush boundaries. The existing NumPy regularization remains unchanged. Captured activation rows below 192 preserve the existing NumPy matrix path; larger calibrated rows use the owned FP32 transform. Existing CPU reconstruction and source/format support remain intact. A first native per-layer LDLQ candidate used the maintained NumPy compensation loop with the exact native trellis primitive. The physical test rejected it:446 of4096 packing words differed after the first32-term cross-buffer product. Native LDLQ therefore stops with an explicit fatal guard before quantization in this slice. A follow-up must qualify owned FP32 compensation before enabling this path.

The frozen Hadamard corpus contains eight independently executed MLX 0.32.2 cases and 197,888 output words: both axes, strided opposite dimension, all basis directions, signed subnormals, oracle scale divisions and 192-row FP16 captures. All words match after explicit FTZ. The original four subnormal differences remain in `hadamard-before-ftz.json`; the corrected result is in `hadamard-after-ftz.json`. Removing FTZ makes the signed regression fail. These checks establish the recorded finite corpus and mathematical Walsh basis behavior; they are not a proof over all floating-point matrices.

`mlxl3_quantizer.capture.read_native_capture` is the host consumer for the agreed source-forward protocol in `capture-protocol.md`. It validates source/request identities, module widths and coverage, row caps, original/capture/storage dtypes, segment prefixes, teacher counts, hashes and finiteness, then opens individual modules lazily. It does not produce or substitute captures. The raw BF16 source graph, bounded source weight ownership, all-expert MoE filling and teacher capture remain model integration work until the actual native producer is exercised.

The test suite distinguishes protocol replay from physical inference. The ordinary advanced-CLI test uses a clearly labeled frozen-protocol child to verify layout, process transport, packing, file writing and reload with MLX imports forbidden. `physical_native_converter_host.py` invokes the actual public CLI with the real native executable and a separately exited MLX oracle; only its completed report can establish physical end-to-end checkpoint parity. It rejects empty, malformed, mismatched, nonfinite and incomplete results and leaves `parity=false` after any failure.

The pinned optional Pony patch is replayed on upstream `8e7fa6b1556f59fc669e25087903b279b9b0346f`; all six touched production converter files must match the vendored implementation byte-for-byte. This synchronization also fixes the patch's pre-existing omission of the single-shard Safetensors reader already shipped in the vendor. The source inventory review accepts only the shared Python cancellation call and patch/workflow references, with no added MLX runtime call.

Remaining scope is explicit: native grouped expert conversion must retain its 15-point coarse/fine interpolated scale search; serial golden search is not evidence for that policy. Raw native source capture, all supported model adapters, Studio validation, and an MLX-free PyInstaller product are pending. The installed app has not been replaced.
