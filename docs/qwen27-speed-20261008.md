## Implémentation et contrats

Mlp::forward_verification exécutait les MLP denses séparément pour chaque
token. La nouvelle option concatène 2 à 4 lignes, applique les projections
EXL3 et SwiGLU existants, puis restitue les lignes dans leur ordre initial.
Garde : M5, hidden5120, gate/up EXL3 groupés et down EXL3.

Le prototype MB3 historique est réutilisé pour M3/MUL1/input5120 et les sorties
16384/K2 ou 34816/K1..3. Le shader et l'ordre des opérations sont inchangés.
Le batch des MLP rend désormais leurs gate/up éligibles à ce dispatch :
les anciens résultats MB3 seuls ne valident pas cette combinaison nouvelle.

Options à définir **avant le démarrage du moteur** :

~~~text
MLXL3_EXPERIMENTAL_DENSE_MLP_BATCH=1
MLXL3_EXPERIMENTAL_GROUPED_MB3=1
~~~

Une valeur absente ou différente de 1 désactive l'option. Les formes hors
garde restent sur les chemins existants. Le défaut du pipeline dense n'a pas
été étendu. Ces options ne sont pas un réglage publié dans Desktop.

La clé Tune ajoute smallm-v1=0/1/2/3 pour distinguer OFF/OFF, batch seul,
MB3 seul et les deux. Les anciennes calibrations ne sont pas utilisées sous
cette nouvelle identité. Le masque et le constructeur de clé réel sont testés.
Le [vrai bridge](measurements/qwen27-speed-20261008/key-bridge.json) renvoie
quatre clés distinctes avec les suffixes attendus ; quatre processus fermés
avec code0 et registre jetable supprimé. Aucune génération dans ce contrôle.

Chemin réel : Bridge/CLI/Tune → Session::advance → Qwen35Moe::verify_mtp →
Layer::forward_verification_dflash → Mlp::forward_verification →
Exl3Group::forward_qmv_batch. Le MLP rejette les entrées vides, plus de8lignes,
les rangs incorrects et les hidden incompatibles avant sélection. Le contrat
dense_mlp_batch borne les conversions/indices ; qmv_grouped_batch_layout
conserve les groupes et tous les chemins de secours. Pas de changement
de quantification ou précision. La soumission progressive existante a aussi
été qualifiée numériquement sur le dense, sans mesure de vitesse propre.
