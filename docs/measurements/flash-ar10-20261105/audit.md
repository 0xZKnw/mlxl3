# Adaptation audit before interpreting speed

Source `83e118cc`, all twelve physical candidate oracles and the shared model/CLI gates passed. Three read-only reviews ran while the exclusive GPU speed campaign continued; no compiler, verifier or other inference ran. No functional defect or hidden fallback was found. This does not establish GPU occupancy or individual performance.

- **A01:** the 640-thread, four-stream normalization geometry already existed. Each selected pair removes one dispatch and a logical 40,960-byte reread, while retaining written Shared and normalized Private allocations (81,920 bytes). Model counter:82/row.
- **A02:** exact K2/Mul1, fixed dimensions and split1 remain; the expert-axis path uses the same dynamic selector. NT2 doubles declared reduction threadgroup storage from4,096 to8,192 bytes/CTA and private accumulators. Occupancy is unmeasured. Component wall-time samples have substantial variance; their medians do not establish a model slowdown.
- **A03:** the up Half materialization/rounding is preserved before canonical SwiGLU. One materialized buffer/dispatch is eliminated. Frozen stock words and a synthetic swapped-Suh mutation passed/rejected as expected.
- **A04:** both distinct Suh transforms remain; prepared storage grows by5,120 bytes per expert and preparation threadgroup storage grows. There is no single-transform identity assumption.
- **A05:** the same ten canonical route bindings and reduction remain, now using checked offsets in one fresh51,200-byte slab. No output copy is introduced.
- **A06:** exact EXL3 tile math and route order remain; z selects a ready expert. Actual model QMV dispatches144 versus1,440. Six small host Vecs per cohort and group-wide WAR dependencies are additional costs; one partial backing imposes stage boundaries across the cohort. No extra fence, CB wait, GPU copy or waiting to fill a cohort. Temporary payload for ten experts with all four options is bounded at approximately281,600 bytes, not process RAM. The six expert PSOs are created even when their options are OFF; startup impact is unisolated.
- **A07:** all36 real GDN paths execute the whole kernel. It removes six intermediate allocations (77,824 bytes/GDN), while still reading/writing6MiB of recurrent state/GDN. Whole uses48CTAs×512threads versus384CTAs×64 for canonical step: same total state threads, coarser grid. Prework uses3/16simdgroups; epilogue1/16, with two CTA barriers. Q/K preparation is recomputed three times per KV head:144 versus80 head preparations including V (+80% preparation arithmetic). Unique history writers avoid races but do not remove duplicate computation. This is a concrete adaptation tradeoff, not evidence that whole-GDN fusion cannot help.
- **A08:** four norm/RoPE dispatches become one, with two Half allocations (13,312 bytes/QSA) removed; exact intermediate Half values remain in threadgroup memory. KV append/COW/blits are unchanged. A barrier and slot loop replace finer RoPE geometry.
- **A09:** attention score traversal and reduction stay canonical, then explicit Half attention precedes canonical Half sigmoid/product. One12,288-byte buffer and dispatch disappear. Only output lanes perform the final gate, adding a serial epilogue to the large attention kernel instead of a separate parallel gate launch.
- **A10:** two12-CTA×256 GEMVs become one24-CTA×256 launch, with identical arithmetic, weights and192bytes of output allocation. Only launch overhead is removed.
- **A11/A12:** separate source audit found no unsafe ownership/range/publication defect; mutex guards end before pread, jobs retain the allocation until both physical reads finish, and completed private foreground victims are retired before reuse. Same cache policy/capacity/workers/logical bytes; EOF/timeout/drop/partial-enqueue recovery is tested. EINTR and positive partial reads rely on std read_exact_at and were not separately injected. The short model gate enables IO options but does not instrument their actual activity; byte-level component activity is independently explicit.

No candidate was rejected solely for a small or drifting individual result. Defaults remain OFF pending the complete speed matrix. Group results cannot attribute a gain to individual members; old UAR options and excluded HC L3/L5 were not re-enabled.
