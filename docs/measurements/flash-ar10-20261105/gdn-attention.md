## Five distinct candidates

| Candidate | Actual missing boundary | Source-derived work affected per generated row | Priority / risk |
| --- | --- | --- | --- |
| GA1: whole native B1/T1 GDN body | Prepare → recurrence → norm/gate still uses global intermediates | 36 bodies; with current default epilogues, four kernels could become one per body | Highest potential here; highest numerical/occupancy risk |
| GA2: joint dense a/b input projections | Two identical-geometry dense gate GEMVs remain separate | 72 small dispatches → 36; optional later cast fusion would remove another 36 | Smaller, low-to-medium complexity; do not advertise a large gain |

### GA1 — one-head whole GDN body, native exact-arithmetic adaptation

**Upstream mechanism and AR eligibility.** oMLX's Qwen4 B1/T1 path puts prework, packed recurrence and norm/gate in one 512-thread group per value head, exchanging typed intermediates through threadgroup memory. Its actual planned-decode caller selects that whole step, not a verification-only function. [Topology and typed stages, lines 379–406](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_gdn_prework.py#L379-L406), [launch, lines 1130–1154](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_gdn_prework.py#L1130-L1154), [actual decode call, lines 2034–2051](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_gdn_prework.py#L2034-L2051).

**Local gap.** `native/src/gpu/gdn.rs:328–370` still materializes conv/Q/K/V, dispatches `gdn_step_row`, then invokes norm/gate. `native/shaders/flash_gdn.metal:23–62` separates prepare and recurrence. The current optional UAR norm/gate fusion removes only the final producer/consumer boundary; this candidate changes the larger prepare/recurrence topology and placement of their intermediate values. Do not count enabling the UAR option as GA1.

**New domain versus history.** `OPT-2026-10-07-RAPID-GDN-PREP-RECURRENCE` was a different MLX/Qwen3.6-35B implementation with quality passing but a strongly drifting speed screen; it was removed. Flash25 tested preparation alone in the old MLX graph and was also removed. Neither validates this native Flash 16-key-head/48-value-head/128-width/conv4 whole-body implementation. The explicit new reason is the independent native backend and a fused whole body around its already-qualified packed recurrence and canonical T17 epilogue. Old negative results remain relevant rather than being erased.

**Minimum prospective port.** Leave EXL3 input/output projections and a/b projections untouched initially. Transcribe current native arithmetic, not oMLX's types: preserve the half convolution/QK normalization boundaries, current packed FMA/shuffle tree, F32 recurrent state and F32 norm materialization before the corrected T17 sigmoid/product. oMLX's intermediate dtype is not automatically our contract. Only one owner may write each shared Q/K convolution-history channel when three value heads share a key head; identical concurrent writes are still a race. Keep old/new recurrent frames and history distinct until Completed, retain trace/public fallback, and gate on actual B1/T1 geometry and supported threadgroup resources. Register pressure/512-thread occupancy could lose despite fewer passes.

**Indispensable future oracle/screen.** Compare all prepare outputs, next history, full recurrent state and gated output against the existing split canonical kernels for initial/nonzero state, then reuse the independent 84-state model archive/full hidden/logits/continuation and late-failure rollback checks. Include the existing T17 subnormal case. Require 36 successful whole-body uses, not equality on a fallback. One common compiled model gate and CLI can cover composition; only after that, MAIN32 against the accepted current baseline. No new giant per-kernel matrix is needed.

### GA2 — joint a/b projection, with a deliberately bounded first variant

**Upstream mechanism.** MLX-LM's GDN defines one combined `in_proj_ba`, and oMLX's planned Qwen4 decode can stack projections before one one-row projection call. [MLX-LM geometry, lines 193–196](https://github.com/ml-explore/mlx-lm/blob/736ab0d8c1d0edc79c3d798044fe6904e2fa23be/mlx_lm/models/qwen3_next.py#L193-L196), [oMLX stacking/plan, lines 1464–1507](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_gdn_prework.py#L1464-L1507), [real decode use, lines 2020–2033](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_gdn_prework.py#L2020-L2033).

**Local gap/minimum port.** `gdn.rs:314–327` invokes the same 2560→48 dense kernel twice for separate immutable half weights. A joint native dispatch can select a or b by group, reuse the same canonical GEMV body and keep two separate zero-offset 48-half outputs. That avoids incompatible offset subviews in the recurrent consumer and needs no requantization or altered packed EXL3 layout. It saves a dispatch per body, not FLOPs or the two output allocations. Existing historical P11/80G discussions were not this native single-row joint dispatch; label it a new backend adaptation of an old idea, not a discovery nobody considered.

The optional larger variant is to absorb the F32→half GDN input materialization into the same producer and move the independent a/b work before qkv/z. That requires unique ownership of every cast-output element and preserves every half rounding; it should not be silently bundled into the first variant. Do not copy the upstream affine-quantized multi-projection layout to EXL3, nor assume projection-specific input preparation/scales can be shared.

**Indispensable future oracle/screen.** Actual a and b words must match both current standalone kernels on real weights and deterministic input, including signs, zero and near-half-rounding boundaries; check both zero-offset destinations and a mutation swapping a/b. Reuse the common model/CLI gate, require 36 joint-projection dispatches, then use MAIN32. This is a smaller candidate than GA1/GA3; its saved launch count alone does not justify calling it a large throughput boost.

### GA3 — fuse short-decode Q/K norm and RoPE, optionally write K directly to the admitted slab

**Upstream AR mechanism.** oMLX's Qwen4 `prep_qk` handles interleaved query/gate projection rows, Q and K RMS normalization and MRoPE in one launch. The dense-arm caller supports one decode row and invokes it before the cache append. [Producer and typed norm/rotation, lines 57–155](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/attn_fused.py#L57-L155), [actual API/geometry, lines 516–561](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/attn_fused.py#L516-L561), [real caller, lines 2910–2931](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/language.py#L2910-L2931).

**Local gap/minimum port.** `native/src/gpu/qsa.rs:499–527` independently normalizes and rotates Q24×256 and K2×256, then blits rotated K into its slab. This happens for each of 12 full-attention layers even below the sparse crossover. One 26-head native kernel can preserve the current `qsa_norm` reduction order, store its intermediate to half threadgroup storage, then apply the existing `flash_rope.metal` operations. Query input stride512 must skip its interleaved gate half; K stride256 differs. Keep outputs separate/zero-offset. A further direct K store to the already-admitted slab can remove the temporary/copy, but it adds cache-offset and write-publication obligations and is a separate variant of this same candidate, not another idea.

The old QSA/RoPE failures showed half-frequency/cast/order differences; native `qsa_norm` and `flash_rope` are the numerical authorities here, not a verbatim 64-thread upstream reduction. No stale KV-slab proposal: capacity doubling/COW already exists and remains intact. Whole-token rollback and published snapshots must still retain their old slabs; a fused append cannot bypass the fork.

**Indispensable future oracle/screen.** Compare Q/K normalized and rotated values against current kernels, including query/gate layout, offsets, rotary64/nonrotary tail, positions0/1 and an existing nonzero-position capture. Check the exact appended K bytes and retained-prefix replay. Trace fallback can retain intermediate tensors. Reuse full finite model/CLI oracles; require12 actual fused prepares per row. This qualifies on MAIN87+32 without invoking sparse-only scoring.

### GA4 — put the QSA gate in the final canonical SDPA store

**Upstream mechanism.** oMLX appends the gate to the existing one-pass/two-pass closing reduction while keeping the attention result's activation-type rounding first. Its caller actually selects the dense arm for short decode. [One-pass closing reduction/gate, lines 280–310](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/attn_fused.py#L280-L310), [dense decode plan, lines 504–512](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/attn_fused.py#L504-L512), [real gate/attention caller, lines 2971–2983](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/language.py#L2971-L2983).

**Local gap/minimum port.** `native/shaders/flash_qsa.metal:82–118` stores half attention, then a distinct `qsa_gate` dispatch multiplies it by the canonical half sigmoid from interleaved qg. `qsa.rs:528–585` owns both intermediate attention and gated buffers. Add a gated store variant of the existing one-pass body: explicitly round each final attention value to half before the same `hc_sigmoid` and half multiplication. Keep the original score/reduction traversal and fast-exp behavior; do not import another online-softmax plan or repartition keys. The current MAIN workload has <1024 keys (`qsa_attention_blocks`), so a one-pass-only first variant is useful; the two-pass/sparse path can remain a tested fallback. GA3 changes preparation, GA4 changes the final attention consumer; they are independent and composable.

**Indispensable future oracle/screen.** Compare every6144 gated half value against current attention→gate on real qg/KV and deterministic sign/zero/saturation/half-boundary gates. Require explicit intermediate half rounding, sentinel coverage of the final head/element, finite full vectors and a mutation omitting the gate/cast. Reuse QSA state/KV-prefix/fullmodel/CLI checks and require12 actual gated-attention stores on short MAIN32. No speed is inferred from147456 temporary bytes or12 fewer dispatches.

### GA5 — physical residual HC write + next HC stream normalization

oMLX has a real decode write-norm kernel, not just deferred command submission. Its fused forward consumes pending branch/gate operands and chooses write-norm while retaining the written stream output. [Operand and producer, lines 812–910](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/hc_fused.py#L812-L910), [decode caller, lines 1305–1347](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/hc_fused.py#L1305-L1347).

The local accepted L1/HC chain still calls `encode_write` then `encode_read` (`hc.rs:493–495`, `gdn.rs` pending continuation); `encode_read` starts a separate `encode_stream_norm_into`. Current `hc_norm` owns four values per thread,640threads per stream, and a fixed20-SIMD reduction (`native/shaders/flash_hc.metal:1–25`). A narrow native variant can compute the exact HC write into those four F32 register values, explicitly materialize their canonical F32 result, store the still-required written stream, and feed the unchanged reduction/normalization tree. It removes a physical kernel and reread, not another CB or the already-solved CPU wait. The written stream cannot be omitted: later residual injection uses it. Up to82 pairs/row are source-eligible; actual activation must establish the count rather than assuming all48+34 routes qualify.

Keep float promotion, branchF16/F32 typed loads, contract-off multiply/add, stream-specific gate, strides and old snapshot owners. Do not copy oMLX's same-dtype16-bit eager rounding into our F32 stream contract. First port only internal F32 rows on the existing same-Metal chained paths; component trace/F16/mixed ownership fallback remains legacy. This is distinct from L1/UAR scheduling, L3's up→mix, L4 down/inject, L5 workspace, and historical FLASHSSD24 projection activation epilogues.

Indispensable future checks: full written and normalized outputs against separate canonical write→norm on real gate/branch/stream values and offsets, float-promotion fallback, mutation of gate/stream indexing; then the common independent84-state/logit/hidden model/CLI gate with actual nonzero fused-pair count and producer-failure/rollback coverage. The source suggests a good first smaller experiment ahead of whole-GDN; its end-to-end benefit is unmeasured.

## Scope and decision limits

These five are not UAR's deferred-MoE wait, GDN output cast, native norm+gate alone, shared SSD queue or fixed residency. They are also not cancelled expert-encoder reuse. GA1 is a larger topology trial, GA2 an input-projection trial, GA3 an attention prologue trial, GA4 an attention epilogue trial, GA5 a physical residual-write/norm fusion. Variants within each row must not inflate the requested count of ten. Sparse QSA GPU selection, long-context SDPA partition tuning, batched verification and prefill-only GEMM are deliberately not counted for the short AR workload.
