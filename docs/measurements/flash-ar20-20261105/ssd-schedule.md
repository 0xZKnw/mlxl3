## Candidate S20-1 — bounded spin before blocking for actual GPU completion

**Implemented upstream:** Strata [mtl_rt.mm830–842](https://github.com/Niko1221/Strata/blob/ffa80d73133ea5c548aefe57889a16e8085a938f/metal/src/mtl_rt.mm#L830-L842) polls command status before the blocking completion call; [wait_mark856–863](https://github.com/Niko1221/Strata/blob/ffa80d73133ea5c548aefe57889a16e8085a938f/metal/src/mtl_rt.mm#L856-L863) exercises this on deferred work. Its source comment attributes substantial wake overhead to about100 waits/token. That is an upstream observation, not an independent M5 measurement. Do not copy its20ms default spin budget.

**Local missing path:** `Metal::command` in native/src/gpu.rs and `MoeOutput::read`/`FlashMoeRow::drain_commands` in gpu/moe.rs call wait_until_completed directly. No exact spin/wait_spin optimization trial was found in opti; loose “spin” matches concern GPU counters or unrelated UI. AR10 reduces waits but still leaves real per-layer completion boundaries, so this targets latency without changing a kernel or deferring publication.

**Small trial:** one tiny bounded host budget, e.g. tens of microseconds, with a separate bound on status polls; stop immediately on Completed/Error, then use the existing blocking call if not terminal. Preserve every error/status check and producer/consumer ordering. OFF is the old wait. It is one mechanism, not a grid of spin budgets. Poll CPU and GPU overlap is intentional runtime behavior, not a second inference.

**Quality/oracle:** actual nonempty finite component/model result equality and required completion counters; terminal Error/Completed, zero budget, exhausted budget and nonterminal states via a real pure decision helper, then Kani on helper budget/state arithmetic. A real long-enough command must exercise fallback and retained owners. No unbounded busy loop, queued GPU event, extra CB or fake synchronization. CPU power/thermal cost and competition with other desktop work remain relevant. The upstream millisecond estimate cannot be applied to every local wait or summed as saved time.

## Candidate S20-2 — pre-encode cold work while reads run, commit only after required reads succeed

**Implemented upstream mechanism:** Strata [run_graph_seg1050–1083](https://github.com/Niko1221/Strata/blob/ffa80d73133ea5c548aefe57889a16e8085a938f/metal/src/mtl_rt.mm#L1050-L1083) records the complete segmented graph before the CPU streaming handshakes; [window.cpp496–498](https://github.com/Niko1221/Strata/blob/ffa80d73133ea5c548aefe57889a16e8085a938f/metal/src/engine/window.cpp#L496-L498) invokes real ExpertStream::at_layer. This is production graph/IO overlap, not the unused ICB microtool. Upstream submits GPU waits before host IO; its process-exit failure handling and unretained references must not be copied.

**New reason vs AR10 reserved idea:** A11 now gives explicit owned destinations and quiescence. An **uncommitted** native cold continuation can bind its future destination while CPU reads proceed. Only after every required record has succeeded and its generation is validated may the command be committed. EOF/timeout drops an uncommitted CB and its view aliases; the worker continues owning the destination through physical completion. This removes the previously identified stranded-GPU-wait hazard and is materially different from UAR's late final-MoE wait.

**Local boundary:** gpu/moe.rs currently launches demanded reads, encodes shared/hot work, then builds FlashExpert::from_backing and cold QMV only after ReadBatch::ready returns. ReadService currently exposes Shared destinations only in Completed; a private preallocated-destination transaction, not a public “ready” lie, is required.

**Composition constraint:** A06 groups whatever experts are already ready. Pre-encoding an entire ten-miss batch would wait for its slowest record and may lose that overlap. Pre-encoding one record at a time loses the expert-axis grouping benefit. A safe minimal discriminant is a single-miss cohort (or an explicitly preregistered fixed small cohort) where no earlier-ready sibling is delayed. Do not silently turn all waves into one cohort. The current profile must establish exposed cold CPU encoding before this larger port is prioritized.

**Quality/oracle:** hold the real IO worker and require that encoding is complete but CB is NotEnqueued and no cache/model state is published; release and compare every contribution and final mix bitwise. EOF, timeout, cancellation, mismatched generation, partial enqueue and abandoned pending transaction must leave no committed work/no stranded event and retain the write owner until all workers finish. Then common logits/hidden/84-state continuation/rollback/CLI, actual “preencoded before read completion” counters. Kani can check the transaction state/commit predicate and offsets, not Metal/IO concurrent memory safety. This is a larger, conditional candidate rather than a promised quick win.

## Candidate S20-3 — per-layer 50/50 SLRU probation/protected admission

**Implemented and attested upstream:** llama.cpp [moe_cache_slru17–154](https://github.com/ggml-org/llama.cpp/blob/2bc46baa9207d098d03741ac394e7faaf1a955b6/src/llama-moe-cache.cpp#L17-L154) has probation/protected lists, promotes repeated hits to the protected half, demotes the oldest protected slot when full, and evicts probation first while protecting the complete selected cohort. [copy532–597](https://github.com/ggml-org/llama.cpp/blob/2bc46baa9207d098d03741ac394e7faaf1a955b6/src/llama-moe-cache.cpp#L532-L597) is its real scheduler caller. [Merged PR30637](https://github.com/ggml-org/llama.cpp/pull/30637) introduced it in33d6135cbe20e90e67d9db1c874fbb4a9dc64b19. The author reports1–5% over LRU on Qwen3.8-Flash-Next/Gemma4 with3060/4500; a reviewer reports a small consistent improvement. The same discussion records a small-cache GLM regression and capacity-sensitive crossover, so the evidence is qualified, not universally positive.

**Local distinctness:** ExpertCache::reserve currently halves frequencies every16calls and selects by decayed LFU plus age (native/src/flash_support.rs1368–1458). No word-boundary SLRU entry exists in opti; the old apparent substring hit was “assertionsLRU”, not a SLRU trial. Use **53slots per layer with the exact same total2544slots**, no global shared bank or GPU insertion/scatter. This distinguishes it from old global ARC/CLOCK/POOL04 failures; it also compares to decayedLFU rather than claiming the upstream LRU result transfers.53/10selected means5.3token sets locally, outside the upstream tiny-cache explanation, but workload still matters.

**Small trial and oracles:** CPU replay existing real routes with exact initial state/warm phases, compare logical misses/read bytes per phase and include MAIN/HOLD; only if useful proceed to native flags. Keep current lease/generation/pending/fill rollback semantics, unique reserved slots, free-before-evict, and protection of every routed expert. An independent simple deque model plus deterministic churn/phase-shift/duplicate/error cases should detect mistaken promotion/demotion. Kani checks actual list/metadata transitions within an explicitly documented finite slot domain. Then exact expert/model/CLI states and instrument actual hits/bytes. A changed cache policy changes what is read, not numerical reduction order; none of its percentage gains may be added to kernel gains without composition measurement.

## Candidate S20-4 — disable speculative OS read-ahead on dedicated expert FDs

**Implemented upstream:** Strata [ExpertStream::open60–64](https://github.com/Niko1221/Strata/blob/ffa80d73133ea5c548aefe57889a16e8085a938f/metal/src/engine/stream.cpp#L60-L64) opens a private streaming descriptor and separately sets F_NOCACHE=1 and F_RDAHEAD=0. No F_RDAHEAD trial occurs in opti. This candidate isolates **F_RDAHEAD=0 only**, retaining the ordinary page cache; it does not resell F_NOCACHE.

**History:** FLASHSSD12-F/G tested/removed F_NOCACHE with an older MLX12-segment read path and unfavorable diagnostic timing/memory pressure. That failure remains. Native now reads one contiguous1,248,012-byte record directly, but changed format alone does not validate bypassing all OS caching. Disabling unwanted speculative neighboring reads is the smaller distinct upstream control.

**Local boundary:** ssd_reads::sources682–698 currently obtains TensorInfo::source and dup/clone handles from the inspected checkpoint. Never call F_RDAHEAD on these shared file descriptions inadvertently: a dedicated expert-read open handle should retain the inspected inode identity (path replacement cannot redirect reads) and report unsupported/error results explicitly. Descriptor setup is outside the per-miss hot loop. Same workers, logical ranges and bytes.

**Quality/oracle:** assert fcntl success in the real path; deterministic bytes at odd/page-boundary offsets, EOF/truncate/path replacement and cleanup; compare all outputs and actual direct-read byte counters. Kani can verify FD-mode admission/offset guards but not Darwin caching. NAND traffic is non-measured unless a qualified sensor exists; do not turn fewer syscalls or lower page-cache pressure into an SSD-physical claim. Mechanism plausible for random expert reads, but upstream has no isolated F_RDAHEAD benchmark in the inspected evidence.

## Candidate S20-5 — merge truly consecutive misses into one no-copy read range (conditional)

**Implemented upstream primitive:** llama.cpp [plan138–151](https://github.com/ggml-org/llama.cpp/blob/2bc46baa9207d098d03741ac394e7faaf1a955b6/src/llama-moe-cache.cpp#L138-L151) sorts misses to align consecutive experts with consecutive slots; [copy574–588](https://github.com/ggml-org/llama.cpp/blob/2bc46baa9207d098d03741ac394e7faaf1a955b6/src/llama-moe-cache.cpp#L574-L588) merges such uploads into one actual transfer. This is host→GPU upload coalescing upstream; adapting it to native pread is an inference, not a claimed upstream SSD implementation.

**Native missing boundary:** one Read per record today, even if two demanded records are physically contiguous in the same file. Existing native reserve already sorts unique IDs, so sorting alone is not new. A genuine trial needs one Shared allocation for the exact adjacent span, one pread, and per-expert checked view offsets with no gather-copy and no gap bytes. FlashExpert::from_backing currently requires exact EXPERT_BYTES, so its owner/view-offset contract must change and A11 multi-owner retirement must stay safe. Fresh allocation fallback can avoid reusing a span while a sibling view is live.

**Admission:** first count actual consecutive same-file demanded ranges in the new profile/route artifact. If negligible, this is source-only reserve and should not be padded into the ten substantial trials. It is separate from A12's splitting one record, A11's storage reuse, old seven-bank alignment/copy compaction, and a common queue. Same logical bytes and cache policy; no threshold tuning or reading holes. Counter exact merged record count/syscall bytes, independent interval oracle, mixed standalone/group owners, EOF in each member and timeout/retain/drop cases; then model/CLI. No speed forecast is defensible from the implementation alone.

## Not counted / lower priority

- **mmap Metal model buffers:** current llama.cpp model.cpp2022–2036 wraps only selected host ranges because Metal wrapping pins them. LOAD09 already rejected per-tensor MLX mapping/offset/page-fault issues. Native direct-record buffers avoid that MLX restriction, but mapping62GB of expert weights would undermine the bounded3GiB cache and introduce page-fault/residency risk; not a new quick AR candidate without a strict bounded mapping design.
- **Global cache/ARC, fixed residency, common queue, A11/A12, old early-shared and next-layer LES prediction:** already studied/implemented or historical negatives, not recounted. Strata's urgent/prefetch queues and cancellation concern depth>0, while the accepted AR20 protocol is depth0.
- **oMLX pending-write hot tier:** paged_ssd_cache.py4211/4250 and4373/4434 checks pending writes before disk. This is real KV/prefix persistence, not expert streaming; prefixOFF/current single-request AR offers no corresponding disk write/read path, so it is inapplicable to this throughput target.
- **Cached FD / metadata batching:** Strata retains its fd and avoids per-record dup/fstat. Native sources currently clones a File per record and validates metadata twice. However the existing POSTP08-LOCAL-REVIEW02 trace already found only0.12615ms/row wall for double-fstat,0.00516ms withoutGPUActive; do not market this as a large new boost. Arc<File> jobs could remove dup/close, but its benefit is unmeasured and the source/TOCTOU/truncate checks must remain. Lower priority than1–4.
- **Parallel host recording:** llama Metal context566–607 and749–786 really records later queued CBs with dispatch_apply while initial work runs. It is distinct from canceled same-expert encoder reuse, but FlashNext's Cell-containing Metal context is not Sync and route-dependent weights/state differ per layer. This is an architectural reserve, not a cheap missing switch or current implementation claim.

No local measurements or verifier claims are attached to this note. Root must select and preregister exact prototypes before implementation, and must not count reserves/inapplicable paths as completed successful tests.
