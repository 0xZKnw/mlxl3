| Local label | Mechanism absent above ALL12 | Evidence / source budget | Suggested priority |
|---|---|---|---|
| GA20-1 | Compute per-head scalar GDN gates once and broadcast within CTA | Whole kernel currently repeats the identical gate expression on all512 lanes/head; upstream uses one producer lane | **First: smallest concrete missing adaptation** |

GA20-2 changes decomposition/reuse; GA20-3 changes load scheduling and can be implemented on either old or new decomposition. They are distinct mechanisms, not two values of a tile parameter. ### GA20-1 — hoist scalar gates out of each recurrent lane

**Actual upstream implementation:** oMLX's whole GDN computes beta and decay on a single lane of otherwise idle simdgroup3, stores one typed beta and one FP32 decay in threadgroup memory, then joins the existing prework barrier. [Declarations and full body396–484](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_gdn_prework.py#L396-L484), [producer470–484](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_gdn_prework.py#L470-L484), real decode [2010–2053](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_gdn_prework.py#L2010-L2053). The upstream [two-step bit-exact state test406–442](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/tests/test_qwen35_gdn_prework.py#L406-L442) covers FP16/BF16/FP32 instantiations against the three-launch path. This is actual implementation/test evidence, not an isolated measured boost.

**Concrete local gap:** native/shaders/flash_gdn.metal:155–174 reaches the packed header with MLXL3_GDN_FUSED_GATES=1; native/shaders/gated_delta_packed.metal:52–77 evaluates the same b sigmoid, softplus(a+dt_bias), exp(A_log) and final decay in every recurrent lane. The whole CTA has512 lanes sharing exactly one h. AR10 preserved the header for arithmetic fidelity but did not port upstream's scalar sharing. No new launch, head partition or removal of state math is needed. Source-level expression evaluation falls512→1 per head (48heads×36bodies/row); compiler SIMD uniformity may already amortize some work, so this is **not512× hardware cost or throughput**.

**Minimum port:** one lane executes our exact existing expressions, including half summed/max/min/softplus, plus_one==1 log1p branch, metal::exp versus precise::exp distinctions, and half beta rounding. Store float decay/half beta, reuse the already uniform barrier, then let the same packed recurrence read those scalars through an explicit precomputed-gates adapter. Do not copy oMLX's sigmoid/log1p arithmetic literally. Public/trace/unsupported/old separate kernel behavior remains the existing path. Both values must be written on every eligible CTA before any read; never place a CTA barrier in a divergent subgroup branch.

**Indispensable checks:** independent current whole/split outputs for every state/history/gated word on two nonzero recurrent steps; finite gate corpus with zero/sign/subnormal/saturation and plus_one==1 boundary; source mutation swapping beta/decay should be rejected by oracle. Full84-state archive/logits/hidden/legacy continuation+CLI gate remains shared. Require36 actual broadcast uses, and ideally report source gate-producer count48 per body. Same source/shader constants/half boundaries, no tolerance relaxation. This is a missing broadcast/hoisting mechanism, distinct from merely enabling A07 or changing its CTA size.

### GA20-2 — canonical SDPA chain decomposition plus paired-head K/V reuse

Upstream [one-pass chains228–281](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/attn_fused.py#L228-L281) computes two queries per K/V load and distributes the32 canonical stripe chains into128-thread groups. [Combine283–311](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/attn_fused.py#L283-L311) retains the existing max/sum/output tree; [actual launch585–607](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/attn_fused.py#L585-L607) is used by language.py's dense branch around2971. HPT2 divides our12queries/KVhead, so a pair never crosses the KVhead boundary.

Local native/shaders/flash_qsa.metal:84ff and its A09 gated-store clone keep one1024-thread CTA/query head,24groups total, no paired K/V loads. Preserve the exact32 stripe chains, each chain's t+=32 order and FP32 accumulations, current /16.0 query scale and the precise existing closing tree; append A09's canonical Half attention rounding and Half sigmoid/product. New decomposition adds a producer+combine boundary and F32 scratch: outs24×256×32×4=786432bytes plus max/sum6144bytes per call. All scratch is temporary; account for it rather than advertising only reduced reads. Two query heads share K/V loads but double per-thread q/o state. At MAIN87..119 keys, extra scratch/launch can outweigh occupancy benefits; no gain is inferred from the geometry.

Actual upstream [FP32 bit-exact tests329–360](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/tests/test_qwen4_attn_fused.py#L329-L360) cover keys1/5/33/130/1000/1023 and two-pass boundaries; [real-layer tests239–260](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/tests/test_qwen4_attn_fused.py#L239-L260) include single-row decode. These are not run locally by this task. Native component oracle should use the independent current one-pass+gate, complete6144words at keys1/33/87/119/130/1023, poison scratch and final-head sentinel, then shared model/CLI; dense short path only initially, with sparse/two-pass fallback preserved. Kani can verify checked scratch extents/grid/head pairing, not SDPA correctness or Metal concurrency.

### GA20-3 — four-key SDPA software pipeline

Upstream [LOAD_K/LOAD_V/SCORE/UPDATE/CHAIN160–224](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_vlm_qwen4_exp_compat/vendor/mlx_vlm/models/qwen4_exp/attn_fused.py#L160-L224) stages four keys/values, computes their scores before the state updates, and issues next K/V loads between updates. It is actually invoked by both chain bodies. The tests linked above exercise that production implementation together with decomposition; no isolated software-pipeline speed result is claimed.

Local one-pass and A09 store-gate bodies still load/score/update a single key at a time. A standalone pipelined-body adapter can preserve each score's eight accumulation steps and every chain's update order0/1/2/3 while moving only independent loads/scores. This can be applied before GA20-2, so its causal mechanism is separate from chain grouping. K/V addresses use the existing dense512-word stride and head/12; keep all partial tails guarded. Prefetched invalid slots must never feed uninitialized scores. Same zero/empty-stripe semantics, fast::exp and Half final gate. Extra register storage for four half K/V packs and four scores is a real occupancy cost. The compiler may already schedule scalar loads, so the independent screen is essential.

Oracle: same complete word/finite/poison corpus as GA20-2, plus lengths31/32/33/127/128/130 for partial four-chain groups and final stripe. Do not count four pipeline depths as four ideas. One common model/CLI gate and measured compatible composition can qualify GA20-2+3; no per-detail full-model campaign is required.

### GA20-4 — resident projection bundles without weight duplication

The real upstream single-row GDN path caches row-concatenated qkv/z/b/a weights in [_one_row_fused_projections1440–1477](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_gdn_prework.py#L1440-L1477), creates a narrow-tile one-row QMV plan [1498–1526](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_gdn_prework.py#L1498-L1526), and invokes it at2016–2037. oMLX also has a direct separate-output same-input [_group_source171–190](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/row_exact_qmv.py#L171-L190), but its public group API currently requires rows>1 [629–643](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/row_exact_qmv.py#L629-L643). Do not mislabel that group API as an already-active one-row path. Source comments at row_exact_qmv:665–673 report narrower one-row tiles closer to DRAM floor on M5 Ultra; no transferred M5 gain.

Native gdn.rs:323–357 still invokes qkv.encode_row then z.encode_row and joint AB separately. QSAforward independently invokes q/k/v projection chains. A resident multi-matrix tile grid can share dispatch setup without sharing distinct Suh transforms, and write separate existing outputs. This differs from A06, which batches routed experts with identical shapes, and from A10, which combines only the two small denseAB GEMVs. Treat GDN and QSA shapes as cases of **one** resident-bundle mechanism. Actual K/codebook/splits/shape compatibility must be inspected before admitting a pair; unlike affine row concatenation, arbitrary EXL3 matrices cannot share preparation or a numerical decoder. Keep dimension/K specialization, canonical H128, FMA and Half boundaries per projection. Avoid concatenating packed weights: that duplicates memory and can invalidate offsets.

This is a larger port than scalar gate hoisting. Required oracle is complete independent current projected words for every bundled output, deterministic strided F16/F32 inputs, distinct projection scales and final-word sentinels; preserve public errors and retained resource owners. Require actual36eligibleGDN pairs or12QSA groups if those formats qualify, not success on fallback, before shared model/CLI and MAIN32. No ten-row routing/cancelled same-expert encoder reuse is involved.

### GA20-5 — quiescent recurrent frame pool, historically weak priority

Actual allocator reuse: MLX [malloc128–171](https://github.com/ml-explore/mlx/blob/c69303b00f5f61860436e832f23fa8c34b96f93a/mlx/backend/metal/allocator.cpp#L128-L171) attempts the size cache before a new Metal buffer, and [free187–203](https://github.com/ml-explore/mlx/blob/c69303b00f5f61860436e832f23fa8c34b96f93a/mlx/backend/metal/allocator.cpp#L187-L203) recycles released buffers below a budget. This is general allocator implementation evidence in the upstream runtime, not a GDN-specific speed result.

Native gdn.rs:289–313 allocates new history+F32recurrent buffers for each nextFrame. A bounded2-frame free list per layer would have to preserve current immutable public frames and every snapshot/prefix/pending producer. Current Frame clones contain Buffer wrappers; Metal itself retains resources while work executes, so a naïve Rc count on state or a buffer retainCount is insufficient. A new private Rc-owned frame plus a completion-bound lease could recycle only an unaliased frame after all submitted uses complete; snapshots pin frames and must force fresh fallback. Never update current state in place before successful completion. Such ownership changes warrant Kani on actual state-machine helpers plus retained-prefix/rollback/abandon/error tests.

**Historical stop signal:** opti.md's I120-P13 diagnostic (near line42 in this checkout) already measured72GDNframe requests/115.458MBlogical payload but only0.247720ms host allocation API/row, and explicitly deprioritized a large state pool. The allocation payload is not memory saved or time recovered. AR10 whole changes temporary allocation traffic but not the frame shape; this alone is not a reason to promise a large pool gain. Wait for the new ALL12 profile, or keep this as an explicit low-priority reserve rather than padding the requested ten.

## Exclusions and next decision

No relaunch of A07 merely with a different512-thread value is proposed; GA20-1 addresses duplicated scalar work. No renewed HC up/mix or workspace/L3/L5. A direct QSA K store after norm/RoPE would be an A08 variant previously documented, not a separate tenth idea. Input-cast fusion into jointAB was already documented as an A10 larger variant and is not counted anew. Long-context QSA partition tuning, prefill batching, MTP verify replay and activation INT8 kernels do not address the requested short native AR screen. GDN QK convolution duplication is an acknowledged A07 tradeoff, not an independent attested new optimization in these read sources.

Suggested order from source alone: scalar gate broadcast first, then canonical SDPA decomposition/pipeline, then eligible resident bundles. No prototype is authorized by this note itself: parent must preregister the exact candidates and protocol, use the current profile, then compile/qualify and measure above ALL12. No measured native gain is claimed here.
