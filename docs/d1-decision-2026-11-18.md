Journal : `opti.md`, entrées `INTEGRATION-2026-11-18-D1` et `INTEGRATION-2026-11-18-D1-OMNI-AUDIO`.
Preuves : `build/d1-20261118/` du checkout principal (non versionné). Branche locale `claude/d1-decision`

## Ce qui est livré (code local)

- **Moteur** : passe « décision » LFM3 (attention `set` sur les couches full-attention, états cachés lus aux
  slots, pointeur pour les lectures), portage CPU complet du prompt et des lectures d1 (`native/src/d1.rs`),
  parseurs stricts nombres/dates (`d1_parsing.rs`), encodeur audio d1-Omni natif (`lfm3_audio.rs` : WAV PCM
  16 bits, rééchantillonnage sinc, log-mel 128, sous-échantillonneur + LFM2 17 couches + projecteur sur MLX,
  nouvelle opération FFI `conv2d` pas 2), chargement `lfm3_omni`.
- **Commandes** : `mlxl3-rs decide <modèle> --request r.json [--trace dir]`, `decide-bridge <modèle>`
  (JSON par ligne : `{"id", "request"}` → `result` / `error`, `ping`), `decide-serve <modèle> --port 8100
  --api-key-stdin` (HTTP : `GET /health`, `/v1/models`, `/v1/capabilities`, `POST /v1/decide`, Bearer exigé,
  médias en `data:` URL seulement, file d'attente 8, 429 au-delà).
- **App** : mode **Decision** à côté de Chat/Agent/Server/Lab. Onglet **Playground** : état texte ou JSON,
  images et clips audio (fichier, glisser-déposer ou enregistrement micro, 5 min max, pas de vidéo), éditeur
  de questions (oui/non, choix, choix multiple, score, texte/nombre/date lus, estimation, boîte, boîtes),
  questions parlées, réponses en barres de probabilité, span surligné dans l'état, boîtes dessinées sur l'image,
  JSON brut. Onglet **Server** : `decide-serve` avec port, accès local/réseau, clé générée, copie de l'URL, de la
  clé et d'une requête curl prête. Le modèle de chat est libéré avant de charger un modèle de décision ; quitter
  le mode arrête le bridge et le serveur de décision. Les modèles sont trouvés dans le registre (config avec
  `d1_attention`) ou ajoutés par dossier.

## Qualité contre le code officiel en FP32 (oracle Modal)

- d1-2B, 12 fixtures (texte, JSON, tokens spéciaux, 30 options, 20 questions, 1 376 tokens d'état, 2 images) :
  mise en page exacte ; 70 slots, KL max 8,3e-4 nat ; probabilités à ≤ 0,0088 ; **réponses identiques, nombres
  et dates compris**.
- d1-Omni-2B, 18 fixtures (+ appel vocal, audio + état, question parlée, français 22 050 Hz, son pur,
  image + audio) : mise en page exacte ; mel ≤ 3,9e-4, features audio L2 relative ≤ 0,0013 sur la parole ;
  réponses identiques sur les 18. **Trois portes échouées, gardées telles quelles** : son pur (écart mel 0,02
  uniquement au plancher de bruit float32 de la référence, énergies < 10⁻⁹) et deux fixtures image (KL des arêtes
  de boîtes jusqu'à 0,066). Avec la tour vision non quantifiée ces deux-là passent (KL max 0,0061 et 0,0023),
  sans revenir au niveau de d1-2B (≤ 0,001 par slot) : la quantification vision explique l'essentiel, pas tout.
- Parseurs : 120/120 cas de l'oracle Python (69 nombres, 51 dates).
