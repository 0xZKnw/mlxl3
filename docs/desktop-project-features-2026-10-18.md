## User journeys

- **Edit / regenerate / branch:** message actions preserve the original conversation and create an independent branch. Editing restores the user text and attachments to the composer; sending is explicit. Regeneration starts a new answer in its own branch. A branch can also continue from any completed message.
- **Projects:** the sidebar selects a project. Each project owns its conversations, instructions, documents, optional opening profile and exact MCP tool allowlist. Removing a project retains its conversations under “No project” and keeps excerpts already saved with messages.
- **Profiles:** save and apply the current model, context, system instruction, sampling and optional output schema. Profiles are stored with the workspace; selecting a project applies its assigned opening profile. Model paths must already be registered.
- **Documents:** add text/PDF files or a folder in Projects → Documents. A deterministic, accent-insensitive keyword search selects up to five excerpts per question (eight in the document search UI), each at most 1,200 characters. This is lexical retrieval, not an embedding or semantic search service. Excerpts retain the source ID, filename, page and original path. Answer links and source buttons open the saved excerpt and, when still available, the original PDF at its page. A source link is resolved only against the answer's saved sources. Verify that a generated claim is actually supported by its source.
- **Limits:** 128 documents and 16 MiB extracted text per workspace; existing attachment limits remain 20 MiB/file and 256 KiB extracted text/file. Folder enumeration stops at 4,000 entries and skips hidden files, packages and symbolic links. Errors and incomplete imports are shown. No OCR is added.
- **MCP:** manage HTTPS/loopback HTTP or local executable servers with form controls, optional advanced JSON, connection tests and per-project tool permissions. Advanced fields are preserved. Writes take the shared lock and atomically replace the configuration from a temporary file created with owner-only permissions (0600), preserving credential privacy during the write. Testing explicitly starts enabled processes and contacts enabled endpoints. Tests have a 30-second deadline; closing the panel cancels the command. A new project permits no tools. The engine filters the advertised tools and checks the exact allowlist again immediately before execution. Unprojected conversations retain the existing global MCP behavior.
- **Model advice:** the catalogue fetches small config files at the resolved commit before downloading weights. It distinguishes supported model families from unknown/unsupported ones and shows a selectable context. Qwen3.5-family metadata with explicit layer shapes gives a theoretical FP16 KV + recurrent/conv-state estimate. Other or incomplete layouts remain “not estimated.” Weight size and RAM headroom advice is conservative guidance, not a guarantee that a checkpoint will load. Prefix cache, MTP, scratch buffers, allocation rounding and macOS are additional.
- **Voice:** Dictate requests microphone/speech access only on action and requires on-device recognition for the UI language. Unsupported on-device recognition fails visibly with no cloud fallback. Recording stops after 55 seconds, on cancellation, conversation change or sending. Reply actions use the system speech synthesizer and provide an explicit stop action. Microphone and actual speech quality require manual hardware QA.
- **Markdown:** export the current conversation, attachment names, errors and saved source excerpts. An in-progress answer is marked partial. Instructions and private MCP configuration are not exported.

## Workspace compatibility

The workspace schema is version 2. Version 1 is read and migrated with empty project/profile/document collections; unknown future versions still block writes. Saves remain atomic and retain the previous readable file as a backup. The import/export JSON workspace includes the new collections. Document text and citations remain available even if an original file moves. Older apps cannot read version 2. Retain a separate version-1 history copy for a downgrade; the rotating `.backup` may already contain version 2 after subsequent saves. This task has not migrated the personal history.

## Validated JSON

The inspector accepts an optional JSON Schema object. An empty field keeps ordinary text generation. MCP is disabled for a structured request. The engine buffers the answer, validates it, and permits at most three generation attempts. Failure, cancellation, an incomplete document or a context/token limit does not produce a successful invalid JSON response. This is **validation with bounded retries, not token-by-token constrained decoding**. Models can still fail to produce a conforming answer.

The HTTP adapter accepts `response_format.type = json_object` or `json_schema` with `json_schema.schema`. Unsupported schema assertions fail before inference. HTTP independently validates the bridge output before publishing it. For SSE, the assistant role may arrive immediately, but content is emitted only after validation; an error has neither a success finish event nor `[DONE]`.

Supported schema assertions: boolean schemas; single/union `type`; `properties`, `required`, boolean/schema `additionalProperties`; `items`; `min/maxLength`, `min/maxItems`, `min/maxProperties`; `minimum`, `maximum`, exclusive bounds; `enum`, `const`, `allOf`, `anyOf`, `oneOf`, `not`, `uniqueItems`. `title`, `description`, `$schema`, `default`, `examples` are annotations. `$ref`, `$defs`, regex patterns, formats and other unsupported keywords are errors. Schema size is limited to 64 KiB, schema nesting to 32, output to 1 MiB. Numeric bounds are restricted to the safe IEEE-754 integer range; JSON floating-point values use serde_json's f64 representation. This is an explicitly supported subset, not a full implementation of every JSON Schema dialect.

A runtime advertises `workspace_features: true`. Desktop rejects structured requests or project MCP permissions against an older runtime instead of silently dropping their constraints.

### What the bounded checks establish

- `structured_length_bounds`: production inclusive-bound comparison over symbolic `usize` value/minimum/maximum, with both bounds present and either/both absent. The deterministic unit check also exhausts 33³ small finite combinations.
- `project_permission_boundary`: production exact-name comparison for symbolic selection between `read` and `write`, a single-item allowlist and the empty list, unwind 16. This is not a proof over arbitrary strings, arbitrary list lengths or the whole MCP protocol.
- `boolean_schema_contract`: production schema matcher on symbolic boolean schema and `null` output only. This does not prove the full schema parser or JSON validator. Its unreachable checks are branches excluded by these concrete value variants.
- `preview_cache_arithmetic`: production checked KV arithmetic over three symbolic `u8` dimensions (0…255), plus a fixed overflowing `u64::MAX` case. This does not prove allocator usage or actual GPU memory.
- Existing CPU harnesses also ran. In particular, the permission harness reports four unreachable checks, and the boolean matcher 65; these follow their restricted concrete domains. Covers were inspected. No assumption was added to hide a valid production case and unwinding assertions remained enabled.
